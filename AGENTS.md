## File Operations

### One rule: always use `action="overwrite"`

`replace` / `insert` / `delete` are **forbidden** - line numbers drift after each operation, causing duplicates and syntax errors.

### Workflow for any file change

```
1. @read_file filepath="target"           # Read complete file
2. Edit in reply                          # Modify what's needed
3. @write_file action="overwrite"         # Write complete content
4. @read_file filepath="target"           # Verify: check syntax, duplicates, correctness
5. @make target="test"                    # Run tests - MUST pass before committing
6. @git_add -> @git_commit -> @git_push     # One at a time, wait for each result
```

### Git tools: one at a time

Never batch git calls. Send `@git_add`, wait for result, then `@git_commit`, wait, then `@git_push`.

## Release

Release-please creates a PR on branch `release-please--branches--master`. To re-trigger or fix the release PR version, use git tools one at a time:

1. `@git_fetch remote="origin"` - fetch latest from origin
2. `@git_checkout branch="release-please--branches--master"` - switch to release PR branch
3. `@git_reset commit="origin/release-please--branches--master" mode="hard"` - reset to remote release branch state
4. `@git_rebase branch="master"` - rebase release PR branch onto latest master
5. `@git_push branch="release-please--branches--master" force=true` - force push to update PR
6. `@git_checkout branch="master"` - switch back to master
7. `@git_merge branch="release-please--branches--master"` - merge release PR into master

### 禁止手动创建或推送 tags

Release-please 在 release PR 合并后会**自动创建** git tags 和 GitHub Releases。在此过程中：

- **不要**使用 `@git_tag` 创建任何 tag
- **不要**使用 `@git_push tags=true` 推送 tags

手动 tag 会与 release-please 的自动化冲突，导致版本混乱或重复 release。

## Testing

Framework: **luaunit**. Files: `test/*_spec.lua`.

### Running tests

Run all tests:

```
@make target="test"
```

Run specific test file(s) with PATTERN:

```
@make target="test" args=["PATTERN=cache"]
```

PATTERN supports shorthand - `cache` expands to `test/**/*cache*_spec.lua`. Full paths also work:

```
@make target="test" args=["PATTERN=test/cache_spec.lua"]
```

### Writing tests

```lua
local lu = require('luaunit')

TestExample = {}

function TestExample:test_something()
  lu.assertEquals(1 + 1, 2)
end

return TestExample
```

CI runs on push to main/master and PRs, across Neovim nightly/stable, ubuntu/windows/macos.

### Test configuration

Tests use mock modules in `test/notify.lua` and `test/logger.lua` to replace the real dependencies. The `test/minimal_init.lua` sets up `package.path` to load these mocks before the real modules.

**Rules:**
- Use `cache.set_path()` with a temp file in `setUp()` to isolate test data
- Clean up temp files and buffers in `tearDown()`
- Mock modules are in `test/` directory and loaded via `package.path`

## Project Overview

**bookmarks.nvim** is a simple bookmarks manager for Neovim, inspired by bookmarks.vim. It uses extmarks for bookmark display, JSON file for persistence, and supports telescope/picker.nvim integrations.

### Dependencies

- `wsdjeg/notify.nvim` - notification display
- `wsdjeg/logger.nvim` - logging framework

### Key Features

- Toggle bookmarks on any line
- Add annotations to bookmarks
- Navigate between bookmarks in current buffer
- List all bookmarks via quickfix list
- Telescope extension support (`:Telescope bookmarks`)
- Picker.nvim source support (`:Picker bookmarks`)
- Bookmarks persist across sessions (JSON cache file)
- Auto-update bookmark positions when lines are modified (via extmark tracking)

### Architecture Notes

- **Extmarks**: Bookmarks are stored as extmarks (`vim.api.nvim_buf_set_extmark`), which enables automatic line tracking when lines are inserted/deleted.
- **Cache**: Bookmarks are persisted to `stdpath('data')/nvim-bookmarks.json` via `cache.lua`.
- **Path handling**: `utils.unify_path()` normalizes paths across platforms (Windows/Unix).
- **Autocmds**: `BufEnter` restores bookmarks on buffer load; `BufWritePost` syncs bookmark line numbers from extmarks.
- **Keymaps**: Defined via `<Plug>` mappings in `plugin/bookmarks.lua`, users map their own keys.

### Keymaps

| Mapping | Action |
|---------|--------|
| `<Plug>(bookmarksToggle)` | Toggle bookmark on current line |
| `<Plug>(bookmarksAnnotation)` | Add/edit annotation |
| `<Plug>(bookmarksNext)` | Jump to next bookmark in buffer |
| `<Plug>(bookmarksPrevious)` | Jump to previous bookmark in buffer |
| `<Plug>(bookmarksClear)` | Clear all bookmarks in buffer |
| `<Plug>(bookmarksListAll)` | List all bookmarks in quickfix |

### Lua API

```lua
local bookmarks = require('bookmarks')
bookmarks.get()                    -- Get all bookmarks table
bookmarks.toggle()                 -- Toggle bookmark at current line
bookmarks.add(file, lnum, text, context)  -- Add bookmark manually
bookmarks.annotation()             -- Add annotation to current line
bookmarks.next_bookmark()          -- Jump to next
bookmarks.previous_bookmark()      -- Jump to previous
bookmarks.clear()                  -- Clear buffer bookmarks
bookmarks.setqflist()              -- Open quickfix with all bookmarks
```

### Configuration

```lua
require('bookmarks').setup({
    sign_text = '=>',           -- Sign column text
    sign_hl_group = 'Normal',   -- Highlight group for sign
})
```
